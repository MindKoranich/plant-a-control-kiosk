# 📖 คู่มือการแก้ไขข้อมูล Kiosk ผ่านไฟล์ `data/kiosk-data.json`

ไฟล์ [data/kiosk-data.json](file:///Users/m/Downloads/plant-a-control-kiosk/data/kiosk-data.json) ถูกออกแบบมาเป็น **จุดศูนย์กลางของข้อมูล (Single Source of Truth)** ทั้งหมดของระบบตู้คีออส `TOMATO OS` เพื่อให้ผู้ดูแลแปลงปลูกหรือผู้พัฒนาต่อสามารถแก้ไขข้อมูลได้อย่างสะดวกรวดเร็ว โดยไม่ต้องแตะต้องโค้ด HTML หรือ JavaScript

---

## 📂 โครงสร้างข้อมูลในไฟล์ JSON

```json
{
  "system": { ... ข้อมูลภาพรวมระบบและรอบการปลูก ... },
  "stages": {
    "1": { ... ข้อมูลระยะที่ 1 (เพาะกล้า) ... },
    "2": { ... ข้อมูลระยะที่ 2 (ต้นกล้า) ... },
    "3": { ... ข้อมูลระยะที่ 3 (เติบโต-ออกดอก) ... },
    "4": { ... ข้อมูลระยะที่ 4 (เก็บเกี่ยว) ... }
  }
}
```

---

## 🛠️ วิธีแก้ไขข้อมูลในแต่ละส่วน

### 1. ข้อมูลระบบภาพรวม (`system`)
| คีย์ (Key) | คำอธิบาย | ตัวอย่างค่า |
|---|---|---|
| `siteName` | ชื่อระบบ/สถานี | `"TOMATO OS"` |
| `chamber` | ชื่อโรงเรือน/ห้องควบคุม | `"Chamber A • Greenhouse 01"` |
| `cropName` | รหัสสายพันธุ์ตัวอย่าง | `"Tomato Specimen 01"` |
| `cropVariety` | ชื่อสายพันธุ์พืชที่ปลูก | `"Cherry Tomato Premium"` |
| `totalCycleDays` | จำนวนวันรวมของรอบการปลูก | `110` |

---

### 2. ข้อมูลระยะการเติบโต (`stages["1"]` ถึง `stages["4"]`)
ในแต่ละระยะ จะประกอบด้วยข้อมูลสำคัญ 6 ส่วนย่อย:

#### A. ข้อมูลทั่วไปของระยะ
- `title`: ชื่อสั้นของระยะ (เช่น `"เพาะกล้า"`, `"ต้นกล้า"`, `"เติบโต"`, `"เก็บเกี่ยว"`)
- `stageHeaderTitle`: ชื่อเต็มประจำระยะในหน้าข้อมูลเพิ่มเติม
- `desc`: คำอธิบายสรุปสั้นๆ สำหรับเป้าหมายประจำระยะ
- `days`: จำนวนวันของระยะ (เช่น `"25 วัน"`, `"35 วัน"`)
- `dayInStage`: วันที่ปัจจุบันในรอบปลูก (เช่น `12`, `35`, `58`, `85`)
- `progressPct`: เปอร์เซ็นต์ความคืบหน้ารวม

#### B. แถบสรุปบนสุด & เมทริกซ์สิ่งแวดล้อม (`cockpit` & `envMatrix`)
- `cockpit.ec`: ค่า EC เป้าหมายด่วน (เช่น `"0.8–1.2 mS/cm"`)
- `cockpit.ph`: ค่า pH เป้าหมายด่วน (เช่น `"5.8–6.2"`)
- `cockpit.temp`: อุณหภูมิโรงเรือนเป้าหมาย (เช่น `"24–28°C"`)
- `envMatrix`: การ์ด 4 ปัจจัย (EC, pH, Temp, Humidity) พร้อมสถานะและสีแสดงผล

#### C. เซนเซอร์หน้าหลัก (`homeTelemetry`)
- `temp`: ค่าอุณหภูมิล่าสุด (°C) และ `tempTarget`
- `rh`: ค่าความชื้นสัมพัทธ์ล่าสุด (% RH) และ `rhTarget`
- `vpd`: ค่าแรงดันไอน้ำในอากาศ (VPD kPa) และ `vpdStatus`
- `fruitOpacity` & `fruitScale`: ระดับการแสดงผลลูกมะเขือเทศบนภาพกราฟิกจำลองต้นไม้

#### D. กราฟและแนวโน้มค่าปุ๋ย/กรด-ด่าง (`metrics.ec` & `metrics.ph`)
- `target`: ช่วงเป้าหมาย เช่น `"1.8–2.0"`
- `current`: ค่าที่วัดได้ล่าสุด เช่น `"1.7"`
- `todayData`: อาเรย์ตัวเลขข้อมูลย้อนหลังประจำวัน (6 จุดเวลา: 06:00, 09:00, 12:00, 15:00, 18:00, ปัจจุบัน)
- `weekData`: อาเรย์ตัวเลขข้อมูลย้อนหลัง 7 วัน (จ. ถึง วันนี้)
- `guideStatus`: ข้อความสรุปสถานะสั้นๆ เช่น `"สมบูรณ์ตามเป้า"` หรือ `"ต่ำกว่าเป้า 0.1"`
- `guideMeaning`: คำอธิบายทางชีววิทยาสำหรับเกษตรกร
- `guideAction`: แนวทางปฏิบัติทันที (เช่น ปริมาณแม่ปุ๋ย A/B ที่ต้องเติมเป็น มล.)

#### E. ขั้นตอนปฏิบัติรายวันและ SOP (`todos`)
แต่ละรายการในอาเรย์ `todos`:
- `time`: เวลาปฏิบัติงาน เช่น `"07:30 น. • เช้าตรู่"`
- `title`: ชื่องานประจำวัน
- `desc`: คำอธิบายสรุป
- `badges`: ป้ายกำกับไฮไลต์ค่าพารามิเตอร์
- `sop.goal`: เป้าหมายของการปฏิบัติงานนี้
- `sop.steps`: ขั้นตอนการทำทีละขั้น (SOP 1, 2, 3)
- `sop.parameters`: ค่าควบคุม (เช่น อุณหภูมิน้ำ, เวลาแช่)
- `sop.warning`: สัญญาณเตือนหรือจุดที่ต้องสังเกตความผิดปกติ
- `sop.consequence`: ผลเสียที่จะเกิดขึ้นหากละเลยหรือไม่ทำตาม

#### F. รายการอุปกรณ์ที่ต้องใช้ (`equips`)
- `cat`: ชื่อหมวดหมู่อุปกรณ์
- `items`: รายการของที่ต้องเตรียม พร้อมชื่อ (`name`) และสเปก/รายละเอียด (`detail`)

#### G. ข้อควรระวังระดับวิกฤต (`warns`)
- `title`: ชื่อความเสี่ยง/โรคพืช
- `severity`: ระดับความเสี่ยง (`"ระดับวิกฤต (Critical)"` หรือ `"ความเสี่ยงสูง (High Risk)"`)
- `symptom`: สาเหตุและอาการที่พบ
- `action`: แนวทางการแก้ไขทันที

#### H. เกณฑ์มาตรฐานคุณภาพประจำระยะ (`benchmarks`)
- `adviceTitle`: ชื่อหัวข้อเกณฑ์คุณภาพ
- `adviceDesc`: คำอธิบาย
- `items`: 4 เกณฑ์คุณภาพที่พืชต้องผ่านก่อนเปลี่ยนผ่านสู่ระยะถัดไป

## ⚡ การโหลดข้อมูลเข้าสู่เว็บแอปพลิเคชัน
1. **ระบบอัตโนมัติ (Dynamic Fetch):** ทั้งหน้าหลัก (`index.html`) และหน้าข้อมูลเพิ่มเติม (`info.html`) จะดึงข้อมูลจาก `data/kiosk-data.json` มาแสดงผลทันทีเมื่อเปิดเว็บ
2. **ระบบสำรอง (Offline Fallback):** หากเปิดไฟล์ผ่าน `file://` ที่เบราว์เซอร์ไม่อนุญาตให้ `fetch` ข้ามไดรฟ์ ระบบจะสลับไปใช้ชุดข้อมูลเริ่มต้นในตัวโดยอัตโนมัติ เพื่อป้องกันหน้าจอว่างเปล่า
